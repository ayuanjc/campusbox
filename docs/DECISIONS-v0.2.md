## 0. 四条裁定（速查）

| ID | v0.1 默认 | **v0.2 裁定** | 变化量 |
|---|---|---|---|
| TBD-01 ★ 上行 | 只走校园 WiFi，PCB 预留 PHY | **加 RJ45，做标配** | BOM +17 元；壳宽 20→46mm；**撞上 RV1106 无内置 MAC** |

| TBD-04 ★ 预算 | BOM ≤100 元 | **单台约 200 元** | BOM 98→146 元；可加 ESP32-C3 + OLED |

一句话结论：**RJ45 + AP 同时要，会让「USB 供电 + 13mm 壳」这条物理底线顶不住。** 所以 v0.2 的核心设计是「硬件给足余量，软件按 VBUS 电压自动降档」——详见 §3 和 §6。

## 1. 裁定一：加 RJ45 —— 撞上一个硬事实

### 1.1 RV1106 没有以太网 MAC

RV1106 的引脚里没有 RMII/MII。它面向 IPC（摄像头），网络需求靠 WiFi 或 USB 解决，**内置 EMAC 是 RV1109/RV1126 才有的**。

所以「加 RJ45」不是「贴一颗 PHY」那么简单，必须选一条路：

| 路线 | 做法 | 成本 | 吞吐 | 风险 |
|---|---|---|---|---|
| **A. SPI 以太网（推荐）** | DM9051（MAC+PHY，SPI 接口，Linux 主线 `dm9051.c`） | +9 元 | 实测 60–90Mbps（SPI 40MHz） | 驱动成熟度需实测；SPI 时钟上限需查 RV1106 datasheet |
| B. W5500（offload） | 硬件 TCP/IP 栈，驱动 `w5100.c` | +7 元 | **只有 10–20Mbps** | 架构不适合当 Linux 网卡做 NAT 上行 |
| C. 换 SoC 到 T113-S3 | 内置 EMAC（RMII）+ 128MB | −10 元 | 100M 满速 | **128MB 内存会 OOM**（规格书 §21.1 已算到 253MB）；且换 SoC = 全部验证重做 |

**裁定：走 A（DM9051）。** 理由：不动主 SoC、不动内存预算、不重做验证；RJ45 的用途是「有线接校园网做上行」，60Mbps 转发远够用（校园网出口普遍 20–50Mbps）。

### 1.2 DM9051 带来的原理图与 BOM 变化

```text
RV1106                          DM9051                      RJ45(集成变压器)
SPI1_CLK/CS/MOSI/MISO  ────────►  SPI 从接口
GPIO(EXP 借一个)      ────────►  INT（中断，省轮询）
GPIO(WIFI_RST 旁)     ────────►  RST
                               TX±/RX±  ───────────────►  TD+/TD-/RD+/RD-
                               25MHz 晶振
```

- 占 SPI1（4 线）+ 1 GPIO（中断）+ 1 GPIO（复位）。SPI1 原本在 E3 扩展焊盘上，**现在被 DM9051 独占，E3 从「预留」变成「已用」**。
- 中断脚必须能配中断——这正好用掉 §21 要求的「2 个中断-capable」之一。
- **E3 空出来以后，8 个 EXP 里少一个可用**：EXP-07（原「外部 Flash / 加密芯片 CS」）撤销，改由 E3 上的 CS 复用（DM9051 与外部 Flash 共享 SPI 总线、各自 CS）。

### 1.3 外壳必须重做（这是最容易被忽略的连带成本）

RJ45 集成变压器座的沉板款最小高度约 **11.5mm**，加 PCB 1.6mm + 顶部元件间隙，**壳内净高必须 ≥13mm**。原设计 32×20×9 装不下。

**新尺寸：46 × 22 × 13 mm**（棒身 + RJ45 侧出，USB 头在另一端）。

- 体积 5.8cm³ → 13.2cm³（翻倍），外观从「U 盘」变成「小方块 + 尾巴」
- 表面积 2216mm² → 3784mm²（**散热反而变好**，见 §6）
- 用户接受度下降是真实代价：这不再是「插上就忘」的 U 盘，而是一个需要放在桌上的小盒子

### 1.4 有线怎么用（软件行为）

| 检测到 | 上行 | WiFi 角色 |
|---|---|---|
| eth0 插上且有 DHCP | **有线** | **纯 AP**，给手机/室友 |
| eth0 无链路 | 校园 WiFi（STA） | AP 按需（默认关，省电省热） |

**这条优先级是本裁定最大的收益**：有线上行时，设备**完全不碰校园 WiFi 账号**，彻底消灭「设备认证把 PC 踢下线」这个 v0.1 里最大的体验坑（原 TBD-09、风险 R-06 的一半）。

## 3. 裁定三：做 WiFi AP —— 电流炸了

### 3.1 把数字摊开

AP 模式意味着 WiFi **持续发射**（STA 模式大部分时间是收）。按 RTL8822CS（2x2，比 8821CS 更适合并发）估：

| 负载 | 3.3V 电流 | 功率 |
|---|---|---|
| SoC @800MHz（转发满载） | 400mA | 1.32W |
| WiFi AP 20dBm 发射峰值 | 330mA | 1.09W |
| DM9051 + RJ45 LED | 100mA | 0.33W |
| **3.3V 合计峰值** | **830mA** | **2.74W** |
| 折算 5V 侧（DCDC 85%） | | **644mA** |

**USB 2.0 标称 500mA（bMaxPower=250）→ 超 29%。** 这不是余量问题，是硬冲突：插在 USB 2.0 口上，AP 满功率 + 有线转发会拉垮主机端口（轻则掉压重启，重则主机报「USB 端口电涌」直接断电该口）。

同时壳内 13mm，1.2W 平均功耗 → 表面温度已在 §6 算到 62°C，**超过 58°C 上限**。

所以「AP + RJ45 + 满功率」在**供电**和**散热**两个方向同时不成立。

### 3.2 三条路，选软的

| 方案 | 做法 | 代价 |
|---|---|---|
| ① **软降档（选定）** | AP 限 12dBm、SoC 限 600MHz、峰值压到 ~480mA | AP 覆盖一间宿舍（10–15m），转发 ~60Mbps |
| ② 声明 900mA（bMaxPower=450） | 只保证插 USB 3.0 口 / 有源 hub | 插 USB 2.0 口可能触发电涌保护；违反「任何口都能插」的承诺 |
| ③ 独立供电口 | 加 Micro-USB 供电 | 破坏「一根线」卖点，用户会插错 |

**选 ①，并且硬件要给 ② 的余量**：限流点设 **750mA**（比 v0.1 的 600mA 抬高），配软启动；这样在 USB 3.0 口（900mA 可用）上能跑满，在 USB 2.0 口上靠软件降档不超 480mA。

### 3.3 新增一个零成本的自适应机制（重要设计）

用 **RV1106 的 SARADC 读 VBUS 分压**（2 个电阻，分压比 1/3），软件每秒采样：

```text
VBUS ≥ 4.75V  → 满档（AP 18dBm / SoC 800MHz）
4.60–4.75V    → 中档（AP 15dBm / SoC 700MHz）
< 4.60V       → 低档（AP 12dBm / SoC 600MHz），并写日志
连续 3 次掉到 <4.4V → 关闭 AP，只保 usb0（保命优先）
```

这比「读 USB 描述符猜主机能力」可靠得多——USB 2.0 端口在 bMaxPower 上是**协商**而非**测量**，主机不一定兑现。

BOM 成本：**0 元**（2 个 0402 电阻 + 一个 ADC 通道）。必须写进原理图：`ADC0 ← VBUS 经 1/3 分压`。

### 3.4 WiFi 芯片要不要换

| | RTL8821CS | **RTL8822CS** |
|---|---|---|
| 天线 | 1T1R | **2T2R** |
| STA+AP 并发 | 支持但分时，吞吐减半 | 支持，更稳 |
| AP 覆盖 | 一间房 | 两间房 |
| 单价 | 16 元 | **24 元** |

**裁定：换 8822CS（+8 元）。** 预算 200 元完全允许，而 AP 是这个产品的卖点之一，1T1R 并发体验会很差。要 2 根 FPC 天线（+2.5 元）。

## 3.5 两种拓扑，软件必须都能跑

```text
拓扑 A（有线上行，推荐默认）
  PC ─usb0─ CampusBox ─RJ45─ 校园墙口（千兆/百兆）
                  └─wlan1(AP)─ 手机/室友
  → 不碰校园 WiFi 账号，无互踢，最稳

拓扑 B（WiFi 上行，无墙口时）
  PC ─usb0─ CampusBox ─wlan0(STA)─ 校园 AP ─Portal
                  └─wlan1(AP)─ 手机
  → 有互踢风险；AP 默认关，用户手动开
```

## 6. 结构放大后的散热复核

新壳 46×22×13：表面积 2(46·22 + 46·13 + 22·13) = **3784mm²**，取有效 70% = 2650mm²。

| 场景 | 功耗 | ΔT（h=15 W/m²K） | 表面温度（环境 25°C） |
|---|---|---|---|
| 待机（usb0 + STA） | 0.8W | 20K | 45°C ✅ |
| 有线转发 60Mbps + AP 12dBm（降档后） | 0.9W | 23K | **48°C ✅** |
| 有线转发 + AP 18dBm（不降档） | 1.2W | 30K | **55–62°C ⚠️** |
| 同宿舍 5 人共用 + AP 满 | 1.4W | 35K | **60–68°C ❌** |

结论：**降档不是省电优化，是热设计的必要条件。** 这与 §3 的电流结论一致——两条独立路径指向同一个设计：软件必须按 VBUS 电压和负载自动降档。

铝壳阳极氧化后辐射系数 0.8+，比裸铝好，这是选阳极的第二个理由（第一个是外观）。

## 10. 要硬件同学重新确认的四件事

1. **DM9051 的 SPI 时钟能不能跑到 40MHz** —— 查 RV1106 datasheet 的 SPI 控制器上限，写进原理图设计说明
2. **RJ45 沉板座选型** —— 先买 3 款样品量实物高度，别照 datasheet 画封装
3. **RTL8822CS 的 STA+AP 并发** —— 向模组供应商要「concurrent 模式验证过的 SDK 补丁」，拿不到就退回 8821CS 且只保证「有线时开 AP」
4. **4 层板 46×22 的阻抗控制** —— USB 差分 90Ω、SDIO 单端 50Ω，问打样厂能否保证（大多数能，但要提前说）
