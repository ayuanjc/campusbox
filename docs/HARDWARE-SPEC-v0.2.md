## 1. 产品定义

### 1.1 一句话

一根 USB 棒，插到电脑上，电脑多出一块网卡，所有流量自动经过棒子里的网关——网关连着校园 WiFi、自动完成 Portal 认证、按规则分流。**电脑上不装任何软件，不写任何注册表。**

### 1.2 为什么是这个形态（给 HW 的背景，决定了后面所有约束）

软件侧原本的方案是在 Windows 上跑一个托盘程序，帮你把「系统代理」设好。这条路线已经验证失败，原因与代码质量无关：

- 写代理设置要动注册表 HKCU\...\Internet Settings；
- 未签名程序被安全软件按**进程树**拦截，返回 WinError 5，派生子进程同样被拒；
- 退出时若未还原，用户整机断网。

把「设代理」换成「多一块网卡」后，上面三条同时消失：

| 老方案 | 新方案 |
|---|---|
| 需要主机端程序 | 零安装（系统自带驱动） |
| 需要驱动签名（EV 证书，年费数千） | **不需要** |
| 需要改注册表，被杀软拦、被 UAC 拦 | 不涉及 |
| 退出不还原 = 断网 | 拔掉自动回退 WiFi |
| 只覆盖 HTTP/HTTPS | 全协议（UDP、游戏、微信、终端） |

**这是本项目存在的全部理由。请 HW 在任何设计取舍上，优先保护「能被 Windows 免驱识别为网卡」这一条。**

### 1.3 明确不做的事（防止范围膨胀）

1. **做 WiFi AP**（可以给手机/室友共享）——v0.2 裁定，见 §18 与 DECISIONS-v0.2 §3。
2. **不做 4G/5G**：上行**优先 RJ45 有线**，无墙口时回落到校园 WiFi——v0.2 裁定，见 §6.4。
3. **不做存储盘**：只暴露网卡功能，不枚举成 U 盘（枚举成 U 盘会触发 Windows 的自动播放/扫描，且用户会往里塞文件）。
4. **不做显示屏**：v1 只有双色 LED，见 [TBD-07]。
5. **不做电池**：完全由 USB 供电。

### 1.4 用户可见行为（这就是验收标准）

~~~text
[插上]
0.0s  USB 枚举开始
0.3s  系统通知「设备已就绪」
0.5s  网络适配器里出现「以太网 2」(USB NCM)，无需任何操作
1.5s  DHCP 完成，PC 得到 192.168.7.x，网关 192.168.7.1
2.0s  默认路由按 metric 排序，usb0 成为首选出口
3.0s  打开浏览器 → 已在代理环境中，校园网 Portal 已由设备完成认证

[拔掉]
网卡消失 → 默认路由回落 WiFi → 一切恢复原样
~~~

### 2.2 数据路径（HW 只需理解，不必实现）

| 流量 | 路径 |
|---|---|
| PC 的 DNS 查询 | usb0:53 → nftables 强制重定向到设备 1053 → 内核按规则返回 fake-ip |
| PC 的 TCP/UDP | usb0 → tproxy 7893 → 按规则选节点 → WiFi 出去 |
| 校园网流量（172.32.0.0/16 等） | usb0 → **直连**，不走代理（Portal 认证的命门） |
| Portal 认证 | 设备自己用 HTTP 和 172.32.253.17 打交道，PC 完全无感 |
| 余额/节点状态 | 设备定期读机场订阅响应头，缓存在本地，供面板查询 |

**给 HW 的一句话**：设备是一个**双口路由器**（一口 usb0 对 PC，一口 wlan0 对校园网），软件侧会把「双口」这件事做好。HW 的任务是把这块板子做成**能被电脑当成网卡**、**能稳稳跑住一个 A7 上的路由程序**、**插一天不烫不重启**。

| 软件事实 | 推导出的硬件硬指标 | 级别 |

## 5. 主控选型

### 5.1 硬门槛推导（为什么 ESP32/STM32 不适用于主机）

软件侧要在设备上跑的是一个完整的 Linux 路由程序（Go 编写、静态链接、常驻约 25MB RSS），加 nftables、dnsmasq、wpa_supplicant、tproxy。这要求：

1. **MMU + 完整 Linux**：内存保护、fork、mmap 都要。MCU + RTOS 不适用（ESP32 的 PSRAM 最大 8MB，且没有 MMU）。
2. **RAM ≥ 128MB**：Go 运行时本身要几十 MB，加内核页缓存。128MB 是红线，256MB 才有余量做 OTA 双分区解压。
3. **USB Device 控制器**：这是形态的根，没有它就不成立。
4. **内置 DDR 优先**：外挂 DDR 需要等长布线 + 阻抗控制，是自研板翻车的头号原因。**选内置 DDR 的 SoC，等于把这个风险直接删掉。**

### 5.2 候选对比

| 型号 | 核 | 内置 RAM | 存储接口 | USB Device | WiFi | 参考价(单片) | 结论 |
|---|---|---|---|---|---|---|---|
| **Rockchip RV1106G3** ⭐ | A7 1.2G + RISC-V MCU | **256MB DDR3L** | SPI NAND / eMMC / SD | **有 (USB2.0 HS OTG)** | 外挂 SDIO | 30–45 | **首选**：内置 DDR 省掉最大风险；资料与核心板最多 |
| Rockchip RV1106G2 | 同上 | 128MB | 同上 | 有 | 外挂 | 25–35 | 备选，内存紧 |
| Allwinner T113-S3 | 双核 A7 1.2G | 128MB | SPI NAND / eMMC | 有 | 外挂 | 22–35 | 备选：双核更稳，但 128MB 是红线 |
| Sophgo SG2002 | A7 + RISC-V | 256MB | SPI NAND / SD | 有 | 外挂 | 30–45 | 备选：生态较新 |
| RK3308 | 四核 A35 1.3G | 外挂 DDR | eMMC | 有 | 外挂 | 35–50 | 不推荐：要画 DDR |
| i.MX6ULL | A7 800M | 外挂 DDR | NAND | 有 | 外挂 | 40+ | 不推荐：性能低、贵 |
| MT7628 | MIPS 580M | 外挂 DDR2 | SPI | **只有 Host，无 Device** | 内置 | 15 | **淘汰**：没有 device 口，做不成网卡 |
| ESP32-S3 | Xtensa 240M | 512KB+PSRAM | SPI | 有（TinyUSB 可做 NCM） | 内置 | 8 | **淘汰**：跑不了 Linux，见 5.1 第 1 条 |

### 5.3 结论与备选

- **主方案：RV1106G3（256MB 内置 DDR3L）+ 外挂 SDIO WiFi 模组 + SPI NAND 或 eMMC。**
- 备选一：T113-S3（若 RV1106 供货或资料有问题）。
- 备选二（降风险）：**买现成 RV1106 核心板，只自画底板**。见第 16 章路线 v0.1。

## 6. 存储与外设

### 6.1 启动介质

| 方案 | 容量 | 单价 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|---|
| SPI NAND | 128MB / 256MB | 4–7 元 | 便宜、焊盘少、RV1106 原生支持 | 坏块管理靠软件；写入慢 | **v1 首选 128MB SPI NAND** |
| eMMC | 4–8GB | 12–18 元 | 稳、快、寿命好 | 贵、BGA 焊盘 | v2 或需要 OTA 双分区富余时 |
| microSD | 8GB | 5 元 | 好改 | 消费者会拔走、触点氧化、突出 | 仅用于研发样机 |

**分区规划（128MB 时）**

~~~text
0x000000  uboot + 环境        ~4MB
0x400000  kernel + dtb        ~8MB
0xC00000  rootfs (squashfs)  ~72MB   ← 只读，A 分区
0x5400000 rootfs B (恢复)     ~16MB    ← 最小可启动系统，仅含刷机与自救
0x6400000 配置分区 (jffs2)     ~4MB    ← 订阅/账号/日志
余量                          ~24MB    ← 预留
~~~

【强约束】必须有一个**独立的恢复分区**，能在主分区损坏时启动并接受 USB 刷机。

### 6.2 DDR

内置，**无布线工作**。这是选 RV1106 的主要理由，不用再讨论。

### 6.3 WiFi 模组（第二关键选型）

#### 6.3.1 第一筛选条件是「驱动在 OpenWrt 主线里」

不是参数好就行。请按这个顺序筛：

1. 该模组的驱动**已在 OpenWrt 主线或 Rockchip SDK 内核里**，且有人报告可用；
2. 支持 **STA 模式 + WPA2/WPA3-个人 + 开放网络**（校园网常是开放+Portal）；
3. 支持 **SDIO 2.0**，接口速率够 100Mbps 实际吞吐（建议 SDIO 3.0 更稳）；
4. 支持外置天线（IPEX），**不要只支持板载 PCB 天线**——金属壳会屏蔽，见 10.2；
5. 有国内 SRRC 认证的模组型号，省一次认证。

候选（按优先级）：

| 模组 | 接口 | 速率 | 驱动状态 | 备注 |
|---|---|---|---|---|
| **AIC8800D80** | SDIO 3.0 | 2T2R 866M | Rockchip SDK 有，社区渐多 | 便宜，需确认固件包可得 |
| **RTL8821CS** | SDIO 2.0 | 1T1R 433M | 主线 + 广泛使用 | 最稳，认的人多，略贵 |
| AP6212 (BCM43438) | SDIO | 1T1R 150M | 老牌稳定 | 速率偏低，802.11n only |
| ESP32-C6 (作协处理器) | SPI/UART | — | 用作「WiFi 应急通道 + 传感器」 | **不建议做主上行**（吞吐低） |

**建议：RTL8821CS 做主选（稳），AIC8800D80 做降本备选。**

#### 6.3.2 天线

- 首选 **IPEX(MHF4) 座 + FPC 天线**，天线贴在塑料壳内壁，远离 SoC 与 DCDC。
- 备选 **PCB 板载 IFA/倒 F 天线**，但要求：天线区域四层全部禁铜（含地），净空 **≥15 × 8 mm**，天线离金属件 ≥5mm，离 DCDC 电感 ≥10mm。
- 【强约束】**天线周围不得有金属外壳覆盖**。见 10.2。

#### 6.3.3 认证

国内销售需 SRRC（无线发射设备型号核准）。**优先选已过 SRRC 的模组**，整机再做一次备案，费用与周期都可控。见 15.3。

### 6.4 以太网（v0.2 已定：加 RJ45，走 SPI 网卡）

如果决定支持「设备走上行有线」，需要加 **10/100M PHY + RJ45（带变压器的集成座）**：

- 成本 +12–18 元，体积 +8mm（RJ45 太高，需选矮款或沉板）
- 好处：① 完全不与 PC 抢同一个校园网账号（重大）② 稳定性碾压 WiFi ③ 延迟更低
- 代价：棒子变「尾巴」，用户接受度下降

**【v0.2 裁定】加 RJ45，作为 v1.0 标配。但有一个硬事实必须先说清：**

> **RV1106 没有内置以太网 MAC**（RMII/MII 是 RV1109/RV1126 才有的）。所以不是「贴一颗 PHY」那么简单。

三条路，选定第一条：

| 路线 | 做法 | 成本 | 吞吐 | 判定 |
|---|---|---|---|---|
| **A. SPI 以太网** ⭐ | **DM9051**（MAC+PHY 一体，SPI 接口，Linux 主线驱动 dm9051.c） | +9 元 | 60–90 Mbps（SPI 40MHz） | **选定** |
| B. W5500（硬件 TCP/IP offload） | 驱动 w5100.c，架构是「MCU 读寄存器」 | +7 元 | 只有 10–20 Mbps | 不适合做 NAT 上行 |
| C. 换 SoC 到 T113-S3 | 内置 EMAC，但只有 128MB DDR3 | −10 元 | 100 Mbps | **128MB 会 OOM**（§21.1 已算到 253MB） |

DM9051 的连接（详见 §11 模块 11）：

~~~text
RV1106 SPI1(CLK/CS/MOSI/MISO) ──► DM9051 ──► RJ45(TD±/RD±)
GPIO(中断，取 EXP-02)         ──► INT
GPIO(复位)                    ──► RST
25MHz 晶振 ──► DM9051
~~~

**连带后果（HW 必读）**：
1. **SPI1 被 DM9051 独占**，§21.6 的 E3 从「预留」变为「已用」；
2. 中断脚用掉 §21.5.2 承诺的「2 个中断-capable」之一，**EXP-02 从此固定为 PHY 中断**；
3. RJ45 集成变压器座沉板款最小高度约 **11.5mm**，**壳内净高必须 ≥13mm**（§10.1 已改）；
4. 好处极大：**有线上行时设备完全不碰校园 WiFi 账号**，从根上消灭「设备认证把 PC 踢下线」（原 TBD-09 的一半、风险 R-06 的一半）。

## 7. USB 子系统【本项目最关键的部分，请重点评审】

### 7.1 为什么是 NCM 而不是 RNDIS

| 主机 | CDC-NCM | RNDIS |
|---|---|---|
| Windows 10 1809+ | **内置驱动，免驱** | 内置，但老版本更认 |
| Windows 11 | **内置** | 内置 |
| Windows 7/8 | 不认 | 认（部分需驱动） |
| macOS | **原生支持** | **不支持** |
| Linux | **原生支持** | 需 usb-rndis 包 |

**结论：主用 NCM。** macOS 与 Linux 也认 NCM，等于一份固件覆盖三类系统。

【强约束】**只做一个配置（configuration），不要同时暴露 NCM 和 RNDIS。** 双配置会让 Windows 有时选错，出现「插上没反应，拔了再插又好了」的玄学故障——这是社区里最典型的翻车方式。

**v0.2 裁定（2026-10-25）：不覆盖 Win7。** 主机门槛 = Win10 1809+ / Win11 / macOS 12+ / Linux 5.15+，一律 NCM 单配置。RNDIS 分支已从仓库移除；若日后必须覆盖老系统，走独立固件 SKU（idProduct 0x0105），不改主线。

### 7.2 端点与带宽预算

- USB 2.0 High Speed（480 Mbps），NCM 用**两对 bulk 端点**（IN/OUT）+ 一个 interrupt（通知）。
- 实测吞吐上限约 **280 Mbps**（受 bulk 调度与主机驱动影响），远超我们需要的 100 Mbps。**带宽不是瓶颈。**
- 端点数量需求：EP0 + 2 bulk + 1 int = 4 个，SoC 的 OTG 控制器绰绰有余。

### 7.3 接口形态（USB-A vs USB-C）

| 方案 | 优点 | 缺点 |
|---|---|---|
| **USB-A 公头** ⭐ | 插哪都认、无 CC 逻辑、结构最简、成本最低 | 新笔记本可能只有 C 口 |
| USB-C 公头 | 适配新机器、可正反插 | 需 CC 下拉；插 A 口要靠 A-to-C 线（此时线内 56k 上拉，设备端 Rd 仍要正确） |
| 双头（C 公 + A 转接） | 覆盖全 | 转接头易丢、增加 BOM |

**建议：v1 用 USB-A 公头（4 脚：VBUS / D- / D+ / GND，沉板或贴片短体）。**

若做 USB-C 版本，硬件要点（这两条错一条就不枚举）：

1. **CC1 与 CC2 各接 5.1kΩ 下拉到 GND**（Rd，声明自己是 sink）。
2. **VBUS 不要直连 5V 电源轨**，中间串 eFuse/负载开关，且 VBUS 分压到 GPIO 作「插上检测」。

### 7.4 USB 信号完整性

- D+/D- 差分对：**90Ω ±10%** 差分阻抗，走线等长（长度差 ≤ 5 mil），全程包地，尽量不打孔。
- 串 0Ω 或 22Ω（视 SoC 参考设计，有的要求 0Ω，有的要求 22Ω 匹配）——**以官方 VBUS/D+/D- 参考设计为准**。
- ESD：D+/D-/VBUS 三线用 **USBLC6-2SC6**（或 IP4220CZ6），器件**放在 USB 座附近，走线先过 ESD 再进 SoC**。
- 差分对下方**地平面完整**，不得跨分割。
- 【参考】USB 差分区到晶振、DCDC 电感的距离 ≥ 5mm。

### 7.5 VBUS 检测（软件要用）

硬件请提供一路 **VBUS_DET** 到 GPIO：

~~~text
VBUS(5V) ──[100k]──┬──[100k]── GND
                   └── VBUS_DET (到 GPIO，3.3V 域)

分压结果：5.0V × 100/(100+100) = 2.50V  →  落在 3.3V 域的确认高电平区间
VBUS 缺失 → 0V  →  确认低电平
~~~

选 100k/100k 的理由：① 2.5V 对 3.3V 域是安全的高电平（>0.7×3.3=2.31V），且不超压；② 总阻 200k，静态电流 25µA，可以忽略；③ 两个同值电阻，BOM 少一个料号。

若 GPIO 不支持 2.5V 输入（少数 1.8V 域 IO），改成 100k/47k 得 1.58V，或加一级 MOS 电平转换。**VBUS_DET 请务必接到 3.3V 域的 IO。**

用途：
1. 上电 30ms 内就知道「我在被电脑供电」→ 决定 LED 行为与是否启用 NCM（未插电时不枚举，省电）。
2. 检测「拔掉」→ 立刻停 WiFi、降频、准备下次冷启动。
3. 掉电预警：VBUS 掉到 4.5V 以下时提前 3–5ms 通知 SoC（用比较器 + GPIO 中断），让文件系统安全落盘——**这条能显著降低配置分区损坏率**。

### 7.6 PC 侧行为（HW 知道原理即可，不需要实现）

~~~text
1 枚举：设备描述符 → 配置 → 两个接口（NCM 控制 + 数据）
2 Windows 加载内置 usbccgp + UsbNcm 驱动，创建设备节点
3 DHCP：设备侧 dnsmasq 发 192.168.7.10–50
4 路由：Windows 按「接口链路速度」自动算 metric
        USB 网卡(480Mbps 报 480000000) → metric ≈ 25–35
        常见 WiFi5/6 → metric ≈ 50–65
        → usb0 自动成为默认出口
5 拔掉：接口消失，默认路由回到 WiFi
~~~

**这里不存在写注册表的动作**，所以安全软件拦不到，这是我们选这条路的核心收益。

### 7.7 枚举失败排查表（给 HW 调试用）

| 现象 | 最可能原因 | 检查点 |
|---|---|---|
| 插上完全无反应，dmesg 无枚举 | VBUS 未到位 / D+ 上拉未使能 / 晶振不起振 | 量 VBUS、3V3；看 UART 启动日志 |
| 出现「未知 USB 设备（设备描述符请求失败）」 | D+/D- 接反、ESD 器件坏、阻抗严重偏离 | 用示波器看 D+ 空闲电平（FS 设备 D+ 上拉 1.5k） |
| 枚举成功但不出网卡 | 只枚举了控制接口、数据接口描述符有误 / 主机侧驱动未加载 | 设备管理器看接口数；Linux 下看 lsusb -v 的 bInterfaceClass=0x0A/0x0D |
| 出网卡但拿不到 IP | dnsmasq 未启动 / 网桥配置错 | 设备侧 ip addr 看 usb0 是否有 192.168.7.1 |
| 拿到 IP 但上不了网 | 转发/路由/masquerade 缺失 | 这不是 HW 的问题，转我 |
| 插上就重启、反复重枚举 | **VBUS 掉压**（见 8.3） | 示波器看 VBUS 在枚举/连 WiFi 瞬间有没有跌到 4.5V 以下 |
| 只在某台电脑上不行 | 该口供电弱（USB3 口带了别的大功率设备）或线材差 | 换口、换 A-to-C 线 |

## 8. 电源树【第二个高风险区】

### 8.1 输入规格

| 项 | 值 | 说明 |
|---|---|---|
| 标称 | 5.0 V | USB |
| 范围 | 4.75–5.25 V | 需在 4.5V 仍正常工作（线损 + 弱口） |
| 稳态电流 | 220 mA | 5V 侧 |
| 峰值电流 | 500 mA，持续 <2ms | WiFi 发射突发 |
| 浪涌（上电瞬间） | 需软启动压到 <600 mA | 电容充电 |
| 反灌保护 | **必须**：防止设备在 SoC 未上电时把 5V 灌回 D+/D- | 见 8.5 |

**申报给主机的 bMaxPower 设 500mA（即 250 个 2mA 单位）。** 不要申报 100mA（不够）也不要超 500mA（合规与稳定性都差）。

### 8.2 负载预算表

| 负载 | 平均 | 峰值 | 备注 |
|---|---|---|---|
| SoC RV1106（A7 800MHz，转发 100M） | 180 mA @3.3V → **120 mA@5V** | 260 mA@5V | 按 0.6–0.9W |
| WiFi 模组（STA 模式，平均） | 50 mA @3.3V → 35 mA@5V | 350 mA@3.3V → **230 mA@5V** | 发射峰值 |
| SPI NAND / eMMC | 10 mA@5V | 40 mA@5V | 写操作 |
| LED + 其它 | 10 mA@5V | 15 mA@5V | LED 限流 2mA |
| 转换损耗（DCDC 85%） | +15% | — | |
| **合计** | **约 200 mA** | **约 520 mA** | 峰值需电容支撑 |

### 8.3 峰值与 bulk 电容计算（这条决定会不会「插上就重启」）

要求：WiFi 发射时 2ms 内，VBUS 跌到 **4.6V 以上**（给 DCDC 留 0.1V 余量，DCDC 最低输入按 4.5V 计）。

~~~text
ΔV = 5.0 - 4.6 = 0.4 V
ΔI = 0.64 - 0.20 = 0.44 A   （v0.2：AP 满功率 + 有线转发的峰值 − 稳态）
Δt = 2 ms

C = ΔI × Δt / ΔV = 0.44 × 0.002 / 0.4 = 2200 µF
再留 40% 余量 → C ≥ 3080 µF → **取 3300 µF**

注：v0.1 只考虑 WiFi STA 发射（ΔI=0.32A → 2200µF）。v0.2 加了 RJ45 与 AP 模式，
峰值电流涨到 644mA（见 DECISIONS-v0.2 §3.1），所以电容必须加大到 3300µF。
若软件降档生效（峰值 480mA），3300µF 的余量更宽松——不会有害，只多 0.4 元。
~~~

**结论（请照做）**

- **2 × 1500µF 或 1 × 3300µF 低 ESR 聚合物铝电解 / 钽聚合物**（ESR < 30mΩ），放在 VBUS 入口。总容量 **≥3300µF**。
- 并联 **2 × 22µF 陶瓷 + 1 × 100nF**（陶瓷负责高频，电解负责 2ms 的储能）。
- **务必并联**，不要只放一颗大电解——大电解的高频阻抗反而差。
- **加软启动/限流**：让上电时电容充电电流被限制（否则主机看到 >500mA 瞬时，可能报「USB 端口电涌」并断电）。

### 8.4 限流与保护

| 功能 | 建议器件类型 | 关键参数 |
|---|---|---|
| 输入限流（软限流，压住峰值持续电流） | eFuse / 限流负载开关（如 TPS2553 类） | 限流点 **750mA**（v0.2 从 600 抬高），带 ILIM 电阻可调，必须带软启动 |
| 反向保护 | 理想二极管或肖特基 | 防设备向主机反灌 |
| 过压钳位 | TVS（SMAJ5.0A） | 钳位电压 < 6V |
| ESD（VBUS/D+/D-） | USBLC6-2SC6 | IEC 61000-4-2 ±8kV |

**限流点选 750mA 的理由（v0.2）**：AP 模式 + 有线转发的 5V 侧峰值实测会到 644mA（DECISIONS-v0.2 §3.1），所以 600mA 会自己把自己限死。抬到 750mA 后：
- 在 USB 3.0 口（900mA 可用）上能跑满，性能不受限；
- 在 USB 2.0 口上靠**软件按 VBUS 电压降档**压到 480mA（见 8.6 的 ADC 机制），主机不会看到超限持续电流；
- 电容补 2ms 峰值、限流管管持续电流，这个分工不变。

**软启动必须有**：上电瞬间 3300µF 的充电电流会被主机当作短路（>1A），没有软启动就会被「USB 端口电涌」保护直接断电。

### 8.5 各电压轨

按官方参考设计，RV1106 通常需要 **3 路以上**：Core（约 0.9/1.1V）、DDR（内置 DDR 的供电引脚，常见 1.35V 或 1.8V）、IO 3.3V、以及 PLL/模拟 1.8V。

**【参考】架构**

~~~text
VBUS 5V ──[eFuse 750mA]──┬──[bulk 3300µF]──┬── DCDC1 → VDD_CORE (按 datasheet)
                          │                 ├── DCDC2 → VDD_DDR  (按 datasheet)
                          │                 ├── DCDC3 → 3V3 (SoC IO + WiFi + LED)
                          │                 └── LDO   → 1V8 (PLL/模拟)
                          └── TVS / VBUS_DET 分压
~~~

- DCDC 选型要求：**轻载高效**（PFM 模式，静态电流 <50µA），因为我们大部分时间只有 200mA。
- 3V3 轨要给 WiFi 峰值 350mA 留余量 → 选 ≥1A 的 DCDC。
- 每路输出：**10µF 陶瓷 + 100nF**（近端）；SoC 每个电源脚就近 100nF。
- 【强约束】**上电时序必须按 datasheet**（Core 先于 IO 或反之，错了会闩锁）。请照抄官方参考设计，不要自创。

### 8.6 掉电检测（强烈建议加）

~~~text
VBUS ──[分压]──► 比较器(阈值 4.5V) ──► GPIO_INT (下降沿)
~~~

软件侧收到中断后会：停止写配置 → sync → 关闭 WiFi → 等 30ms。**这一颗几毛钱的比较器，能把「用几个月后配置分区坏掉」的概率压到很低。**

### 8.7 复位

- 一颗 RC 复位（10k + 100nF）给 SoC 的 RESET 脚。
- **额外引出一个硬复位**：由（可选）ESP32-C3 supervisor 或按键长按 10s 拉低——用于软件完全卡死时。
- 【参考】复位按键与「恢复出厂」按键**共用**（按时长区分），减少开孔。

## 9. 热设计【第三个高风险区】

### 9.1 热源与功耗转热

| 热源 | 典型 | 峰值 |
|---|---|---|
| SoC | 0.55 W | 0.9 W |
| WiFi 模组 | 0.15 W | 0.6 W（发射瞬时） |
| DCDC 损耗 | 0.10 W | 0.15 W |
| **合计** | **约 0.8 W** | 1.4 W（瞬时） |

### 9.2 壳温估算（请按这个表复核你的结构方案）

自然对流 + 辐射，综合换热系数取 **h ≈ 12 W/(m²·K)**（小尺寸物体偏保守）。

v0.2 尺寸改为 **46×22×13**（表面积 3784mm²，取有效 70% = 2650mm²），功耗因 AP 模式上升。重新算：

| 场景 | 功耗 | ΔT（h=15） | 25°C 环境壳温 | 判定 |
|---|---|---|---|---|
| 待机（usb0 + STA） | 0.8 W | 20 K | 45°C | ✅ |
| 有线转发 + AP 12dBm（**降档后**） | 0.9 W | 23 K | **48°C** | ✅ 目标状态 |
| 有线转发 + AP 18dBm（不降档） | 1.2 W | 30 K | **55–62°C** | ⚠️ 接近上限 |
| 5 人共用 + AP 满功率 | 1.4 W | 35 K | **60–68°C** | ❌ 不可接受 |
| 同尺寸塑料壳 | 同上 | 散热差 3–4 倍 | 壳 70–85°C | ❌ 禁止 |

**结论：降档不是省电优化，是热设计的必要条件**（与 8.4 的电流结论指向同一件事）。铝壳 + 导热垫仍然强制，但只靠结构救不回来，必须有软件降档（9.4）。

【强约束】**用金属壳，并且用导热垫把 SoC 顶面贴到壳上。** 塑料壳在 U 盘体积里等于把 SoC 闷在 90°C 里，跑 4 小时必降频或重启。

### 9.3 结构上的散热措施

1. SoC 顶面 → **导热硅胶垫（1.0–1.5mm，导热系数 ≥1.5 W/mK）** → 铝壳内壁。
2. 铝壳**阳极氧化**（氧化层薄，不影响导热；黑色更利于辐射散热）。
3. **不要在外壳开大面积散热孔**——灰尘与静电入内，且 U 盘体积开孔收益很小。
4. PCB 上 SoC 周围铺**大面积地铜 + 多个过孔阵列**（把热导到背面地铜）。
5. WiFi 模组与 SoC 之间留 2mm 间隔，别贴着（两个热源贴着会互烤）。

### 9.4 软件侧的降频承诺（HW 可依赖）

**v0.2 的三档降档表**（软件实现，HW 只需保证硬件支持）：

| 触发条件 | SoC 频率 | WiFi 功率 | 总功耗 | 用途 |
|---|---|---|---|---|
| VBUS ≥ 4.75V | 800 MHz | 18 dBm | 1.2 W | 满档（USB 3.0 口） |
| VBUS 4.60–4.75V | 700 MHz | 15 dBm | 1.0 W | 中档（多数 USB 2.0 口） |
| VBUS < 4.60V | **600 MHz** | **12 dBm** | 0.9 W | 低档（供电差的 hub / 长线） |
| 连续 3 次 < 4.4V | 600 MHz | **关 AP** | 0.8 W | 保命（只保 usb0） |

**HW 需要提供的物理基础**：VBUS 经 **1/3 分压进 ADC0**（两个 0402 电阻，成本 0 元），软件每秒采样。这是 8.6 掉电检测之外的另一路采样，可与掉电检测共用分压网络。

另外：**AP 默认 10 分钟无客户端自动关闭**——这是热与电的双重需要，不是体验取舍。

**外观定性变化（要跟用户说清）**：这不再是「U 盘」，是「小方块 + 短尾巴」。文案与渲染图都要按这个来，别再用 U 盘类比（风险 R-15）。

### 10.2 【最容易翻车】金属壳 + 内置天线的冲突

**金属壳会把 WiFi 完全屏蔽。** 三条出路，任选其一：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 塑料天线窗** ⭐ | 铝壳上做一块 8×20mm 的塑料/PC 件（或激光开窗后贴 PC 片），天线正对这里 | 结构多一个件，成本 +1 元 |
| B. 全塑料壳 + 内部金属屏蔽罩贴 SoC | 散热靠屏蔽罩导到外壳 | 散热差，壳温高 8–12°C |
| C. 外置 FPC 天线伸出壳外 | 信号最好 | 丑、易断、用户会扯 |

**建议 A：铝壳主体（散热）+ 短边一小块 PC 塑料件（天线窗）+ IPEX 转 FPC 天线贴在内壁。**

判定方法：天线窗正对区域内**金属件一律不许进**（螺丝、卡扣金属簧片、屏蔽罩）。

### 10.3 插拔应力（U 盘形态的头号失效）

- USB 头是**唯一受力点**。PCB 上必须有**两个通孔焊盘或加强筋**，且头部与壳体之间做**机械限位**（让力传到壳，不传到焊盘）。
- 【参考】USB 头 4 个焊盘做**长焊盘（≥2mm）** + 两侧各加一个**固定脚焊盘**（选带固定脚的 A 头）。
- 【参考】PCB 在 USB 头附近不要放 0402 元件（弯折会先崩元件）。
- 目标：侧向 30N、纵向 20N 不脱焊。

### 10.4 其它

- 拔出力：USB-A 标准 10–20N，选正规座子即可。
- 跌落：1m 六面跌落不失效（U 盘重量轻，主要是壳裂与 USB 头变形）。
- IP：不要求，但壳体需有基本缝隙控制（防口袋绒毛）。

## 12. PCB 设计规则

### 12.1 叠层（4 层，1.6mm，沉金 ENIG）

| 层 | 用途 | 铜厚 |
|---|---|---|
| L1 | 元件 + 信号（USB 差分、SDIO） | 1 oz |
| L2 | **完整地平面**（不许开槽） | 1 oz |
| L3 | 电源平面（3V3 / 1V8 / CORE 分区） | 1 oz |
| L4 | 信号 + 地铜（SoC 背面大面积地，做过孔阵列散热） | 1 oz |

### 12.2 关键走线

| 信号 | 要求 |
|---|---|
| USB D+/D- | 90Ω 差分，等长 ≤5mil，包地，尽量不打孔，长度 ≤30mm |
| SDIO CLK/CMD/D0-D3 | CLK ≤30mm，包地；数据线等长 ±2mm；串 22Ω（视模组要求） |
| SPI NAND | 等长、加串阻、远离 SDIO |
| 晶振 | 走线 ≤5mm，包地，下方挖空或完整地，远离 DCDC |
| 天线馈线 | 50Ω 共面波导，长度 ≤15mm，两侧地过孔密集 |
| DCDC 开关节点 | 面积最小化，远离天线与晶振 |

### 12.3 电源完整性

- 每路 DCDC 输出：22µF + 10µF + 100nF。
- SoC 每个电源引脚：100nF（就近，过孔直连平面）。
- 入口：2200µF 电解 + 22µF×2 + 100nF。

### 12.4 天线区禁布

天线正下方与周围 **15 × 8 mm**：L1–L4 **全部禁铜**（含地、含丝印以外的任何铜），且不得有金属结构件、电池、螺丝。

### 12.5 其它

- 板边留 0.3mm 无铜（V-cut/铣边）。
- 测试点直径 ≥1.0mm，标注网络名。
- 丝印标 SN 二维码位置（量产要打码）。

## 16. 版本路线

| 版本 | 形态 | 目的 | 周期 | 成本 |
|---|---|---|---|---|
| **v0.0 验证** | 买现成 RV1106 核心板 + 飞线接 WiFi + USB 线引出 | **只验证一个假设：Windows 认成网卡** | 1 天 | 150 元 |
| **v0.1 底板** | 自画 2 层底板（核心板贴上去），含电源、USB 座、LED/按键 | 软硬件联调，实测功耗/壳温/降档门限 | 2–3 周 | 打样 300–600 |
| **v1.0 一体化** ⭐ | 4 层板，SoC 上板，**含 RJ45（DM9051）**，铝壳 46×22×13 | **可交付的成品**（v0.2 把有线从 v1.1 提到这里） | 8–10 周 | 打样 800–1200 |
| **v1.1** | 加 ESP32-C3 supervisor + RTC | 硬看门狗、掉电通知、时间戳 | +3 周 | +7/台 |
| **v1.2** | 加 0.96" OLED | 不接电脑也能现场看 IP/余额/状态 | +2 周 | +9/台 |

**v0.2 的排序变化**：原计划「v1.0 只有 WiFi、v1.1 再加有线」，现改为 **v1.0 直接上有线**。理由：RJ45 不是「可加可不加的便利功能」，它是**唯一能彻底消灭「设备认证把 PC 踢下线」的手段**（§6.4 连带后果第 4 条）。把这块推后，等于让首版用户先吃一个已知的伤害。代价是首版周期从 6–8 周变 8–10 周、打样费多 30%（多打了 RJ45 区）。

**强烈建议走 v0.0 → v0.1 → v1.0，不要跳。** v0.0 花 150 元一天，能避免「画完 4 层板才发现 Windows 不认」这种灾难。

# 21. 软件资源预留与扩展接口【给未来留空间，v1.0 冻结前必须逐项签字】

> 这一章是「软件向硬件提出的预留要求」。核心思想：**不写进预算表的余量等于没留。** 每一项都给了具体数字，v1.0 冻结时必须能回答「已用 / 剩余 / 冻结值」。
> 三条总原则：
> 1. **算力与内存留 40% 余量**（不是 10%，因为我们还没写完功能）；
> 2. **板上留出一处「什么都不做」的空白区**（见 21.9）——这是最便宜的未来保险；
> 3. **所有预留接口都用焊盘形式引出，不装连接器**（零成本、零体积、零故障点）。

## 21.1 内存预算（这条决定选 RV1106G3 还是 G2）

| 用途 | 常驻 | 峰值 | 说明 |
|---|---|---|---|
| 内核 + 驱动 + 页缓存 | 70 | 110 | 页缓存可回收，不算真占用 |
| mihomo（规则 + 连接池） | 35 | 60 | 规则 2 万条时约 50MB |
| dnsmasq | 3 | 5 | |
| wpa_supplicant | 4 | 6 | |
| 面板 httpd + 静态 | 3 | 6 | |
| portal 认证脚本（busybox sh + curl） | 1 | 2 | **不装 Python**（省 25MB） |
| init / busybox / 日志 | 2 | 4 | |
| **已用小计** | **118** | **193** | |
| **未来预留**（插件、抓包、第二路代理、统计） | — | **60** | 硬留，不得挪用 |
| **合计需求** | | **253** | |

**结论：256MB 是刚好够，128MB 会在大规则集下 OOM。** 这是 RV1106G3（256MB）而不是 G2（128MB）的唯一理由，请勿降配。

## 21.2 CPU 预算

| 场景 | A7 占用（800MHz 基准） |
|---|---|
| 待机（在线、无流量） | 3–6% |
| 转发 100 Mbps（TCP 混合） | 35–50% |
| 转发满速 + 面板打开 | 45–60% |
| Portal 认证瞬间 | 15%（2 秒内） |
| **未来预留**（测速、流量统计、抓包、第二层隧道） | **留 40%** |

软件会把 A7 限制在 800MHz。**HW 按「CPU 长期 ≤60%、平均功耗 0.8W」做热设计**，剩下 40% 是我留给自己的。

## 21.3 协处理器（RV1106 的 RISC-V 核）

若器件确实带独立的 RISC-V 协处理器（**以 datasheet 确认，我不假设**），软件侧计划用它做三件事——这三件事恰好是「主 CPU 崩了也要活着」的：

1. **硬看门狗**：A7 主程序喂狗，超时 60s 拉 RESET
2. **掉电处理**：VBUS 掉电时立刻通知 A7 落盘，再断电
3. **LED 呼吸/闪烁**（主 CPU 睡眠时也能维持）

**HW 需要做的**：确认该核是否可独立编程、有无独立时钟与复位、是否需要外部晶振；若资源不足，退回用外部 ESP32-C3 承担（6.7 已预留）。

## 21.4 存储预算与分区表【建议改 eMMC】

### 21.4.1 先看结论：v1.0 建议直接用 eMMC 4GB（+9 元）

128MB SPI NAND 的实测压力：

| 内容 | 大小 |
|---|---|
| rootfs（mihomo 25MB + 内核模块 + busybox + 面板 + GeoIP 2MB） | 45–58MB |
| 独立恢复分区（最小可启动 + 刷机） | 18–22MB |
| 内核 + uboot + 环境 | 10MB |
| 配置分区（订阅/账号/日志/证书） | 8MB |
| 工厂区（校准/SN/MAC） | 2MB |
| **合计** | **83–100MB** |

128MB 标称，扣掉坏块与元数据实际可用约 110–118MB → **余量只剩 10–30%**，一旦未来想加一个功能就撞墙。

**9 元换 4GB，这是整张 BOM 里性价比最高的一笔。请 v1.0 就上 eMMC。**

### 21.4.2 分区表（eMMC 4GB 版，软件侧冻结）

| 分区 | 大小 | 文件系统 | 挂载 | 用途 | 余量要求 |
|---|---|---|---|---|---|
| loader | 4 MB | raw | — | 一级引导 | 固定 |
| uboot | 4 MB | raw | — | 二级引导 + 环境 | 固定 |
| boot | 32 MB | ext4/vfat | /boot | kernel + dtb + 启动脚本 | ≥50% |
| rootfs_a | 512 MB | squashfs | / | 系统 A（只读） | 实际用 60–90MB |
| rootfs_b | 512 MB | squashfs | — | 系统 B / 恢复（只读） | 实际用 25MB |
| data | 1 GB | ext4 | /data | 配置、日志、订阅缓存、证书 | **≥70% 空闲** |
| factory | 16 MB | ext4(ro) | /factory | MAC/SN/校准/RF 参数 | 固定 |
| **future** | **1 GB** | 未格式化 | — | **给未来功能整块预留** | 100% 空闲 |
| 余量 | ~1 GB | — | — | 坏块/扩容 | 不得挪用 |

**/data 的 70% 空闲不是浪费**：日志环形缓冲、抓包文件、订阅多份历史、OTA 下载临时包，全在这里。经验值——一个每天掉线 5 次的校园网环境，日志一个月能写 90MB。

**future 分区的作用**：未来要加「本地流量统计库（SQLite）」「DNS 黑名单大表」「TLS 证书缓存」这类吃空间的功能，不需要重新分区（重新分区要动 bootloader，是产线事故）。

### 21.7.2 序列号里编码能力位（重要）

软件需要知道「插上的这块板子支持什么」，避免固件与硬件能力错配。请求 HW 按此格式烧写：

~~~text
iSerialNumber = "CB" + <hwrev 2位> + "-" + <feature 2位> + "-" + <sn 8位>
例：CB01-F0-00001234
    hwrev=01（v1.0）
    feature=F0：bit7=WiFi  bit6=RJ45  bit5=OLED  bit4=协处理器  bit3..0 保留
    sn=00001234
~~~

**好处**：软件插上就能读到硬件版本与能力，不需要额外协议、不占端点、不需要第二个 USB 接口（避免触发 Windows 驱动匹配问题）。

### 21.7.3 【明确不做】不要加第二类 USB 接口

不要加 **大容量存储（MSC）**、**HID**、**串口（ACM）** 接口。原因：

- MSC 会触发 Windows 自动播放/扫描 → 用户会往里拷文件 → 空间被占、还会引出「这盘怎么格式化」的售后；
- 多接口会改变设备描述符结构，增加「某台机器匹配错驱动」的概率；
- **所有配置与调试通道都走 NCM 之上的本地 HTTP（192.168.7.1:8080）**，零硬件成本。

未来若真要「免 IP 的配置通道」，方案是 **mDNS 名字（campusbox.local）+ 固定端口**，而不是加 USB 接口类。

### 21.8.3 MAC 地址（这条影响硬件）

| 接口 | MAC 来源 | 可否修改 |
|---|---|---|
| 设备自身（eth/wlan） | 模组出厂 or factory 分区 | 可（从 factory 读，覆盖模组默认） |
| usb0（对 PC 侧） | **软件生成，存 factory** | **必须可改** |
| wlan0（校园网侧） | 模组自带 | **必须可改成随机/指定** |

**为什么强调「必须可改」**：校园网 Portal 认证可能按 MAC 绑定或限速；设备 MAC 与 PC 的 MAC 撞了、或被封了，软件要能换。**若把 MAC 烧死在 OTP 且不可覆盖，这个产品在校园环境里会直接瘫痪。**（对应风险 R-06）

## 21.9 【最便宜的未来保险】板上留一块空白区

**【强约束】PCB 上预留一处 ≥ 15 × 12 mm 的空白区**（在 WiFi 模组与 USB 座之间或背面）：

- 该区域 **不布任何元件、不走任何信号**，只铺地并打散热过孔；
- 预留 **3V3 与 GND 的宽铜（≥20mil）** 延伸到该区；
- 位置选择原则：**尽量靠近 E4 开发者汇流排**，这样未来「加芯片」时可以飞线 + 贴片两用。

**这块空白区能干什么**（都是真实可能发生的事）：

| 未来需求 | 需要的芯片 | 占位 |
|---|---|---|
| 加 ESP32-C3 supervisor（硬看门狗 + 独立 WiFi 应急通道） | QFN32 5×5mm | 25mm² |
| 加 10/100M PHY（转有线版） | QFN32 | 25mm² |
| 加 SPI 加密芯片（防固件被抄） | SOP8 | 20mm² |
| 加第二路 DCDC（外设供电） | SOT23-6 | 10mm² |

**成本：0 元。收益：任何一次「v1.1 想加个东西」都不必重画板（重画 = 重新打样 + 重新调试 + 2 周）。**

## 21.10 核心板接口标准（如果走 16 章的 v0.1 路线）

如果 v0.1 用「核心板 + 自画底板」，那么**底板与核心板的连接定义就是未来升级的接口**。请按此定死（30pin 或 40pin 半孔/排针）：

| 组 | 信号 | 备注 |
|---|---|---|
| 电源 | 5V_IN / 3V3_OUT / GND×4 | 3V3 由核心板供还是底板供，**必须二选一写死** |
| USB | DP / DN / VBUS_DET | |
| 存储 | 无（在核心板上） | 若 eMMC 在核心板则无需引出 |
| SDIO | CLK/CMD/D0-D3/RST | 给 WiFi 模组 |
| 调试 | UART0_TX/RX | |
| 扩展 | EXP-01..04 + I2C0 + UART1 + SPI1 | 与 21.6 的 E4 一致 |
| 复位 | RESET_IN / RESET_OUT | |

**这样做的价值**：未来 SoC 换代（RV1106 → 下一代），**只换核心板，底板与外壳全部复用**。外壳开模（5000–12000 元）不会打水漂。
