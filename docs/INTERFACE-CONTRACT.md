# 软硬件接口契约 v0.2

> v0.2（2026-10-25）变更：RJ45 成为 v1.0 标配（DM9051 经 SPI1）、WiFi AP 模式加入、限流点与输入电容上调、新增 VBUS ADC 采样、EXP-02 被以太网中断占用。变更点在后文以 **[v0.2]** 标注。

**用途**：硬件与软件之间唯一的一页纸。任一方想改这里的内容，必须双方同意并升版本号。
**原则**：软件依赖的硬件能力，全部在这一页里；这一页没有的，软件不许假设。

---

## 1. 身份与枚举

| 项 | 值 | 可改 |
|---|---|---|
| idVendor | `0x1D6B`（Linux Foundation，免申请）或自备 | 自备则需注册 |
| idProduct | `0x0104` 基础版（v0.2 起已含 RJ45）/ `0x0105` 预留未用 / `0x0106` 双口（预留） | 需双方同意 |
| bcdUSB | `0x0200`（USB 2.0 High Speed） | 否 |
| bcdDevice | 与**硬件版本**对齐：v1.0 硬件 → `0x0100` | 随硬件版本走 |
| MaxPower | `250`（= 500mA）。**[v0.2]** 满档实测峰值 644mA，靠 VBUS 降档压在 500mA 内；**不虚标 bMaxPower** | 需硬件确认 |
| USB 配置数量 | **恰 1 个** | 严禁增加 |
| 接口 | 接口0 = CDC-NCM 控制（class 0x02 / subclass 0x0D）；接口1 = CDC-Data（class 0x0A） | 否 |

### 1.1 iSerial 格式（软件靠它判断硬件能力）

```text
CB  <hwrev:2>  -  <feature:2>  -  <sn:8>
│      │             │              │
│      │             │              └ 8 位十进制序号，出厂唯一
│      │             └ feature 位图（十六进制 2 位）
│      └ 硬件版本：01 = v0.x, 02 = v1.0
└ 产品代号
```

feature 位定义（**只增不改**，保留位写 0）：

| bit | 含义 |
|---|---|
| 7 | WiFi（v1.0 必有 → 0x80） |
| 6 | RJ45 有线口（v1.0 起必有 → 与 bit7 合成 `0xC0`） |
| 5 | OLED / 本地显示 |
| 4 | 协处理器（ESP32-C3 supervisor） |
| 3–0 | 保留，写 0 |

示例：`CB01-F0-00001234` = v0.1 硬件、有 WiFi、无 RJ45、序号 1234；`CB02-C0-00001234` = v1.0 硬件、有 WiFi + RJ45。

**软件行为**：能力位为 0 时，软件不得调用对应功能（例如无 RJ45 时 `prefer_wired` 强制为 0 且面板不显示有线状态）。版本解析失败时按最小能力集（仅 WiFi）处理。

## 2. MAC 地址

| 接口 | 来源 | 必须可改 |
|---|---|---|
| usb0 | `/factory/mac_usb0`，缺失则用 `02:aa:bb:cc:dd:01` | **是** |
| wlan0 | `/factory/mac_wlan`，缺失则用芯片默认 | **是** |

**为什么必须可改**：校园 Portal 可能按 MAC 绑定账号或封禁 MAC。烧死在 OTP/efuse 里，产品在该校园环境就永久不可用，只能换板。这是风险 R-06。

出厂 MAC 段建议本地管理地址（第二字节 bit1=1），例如 `02:CB:xx:xx:xx:xx`。

## 3. GPIO 分配

### 3.1 已占用（软件必需）

| 信号 | 方向 | 中断 | 语义 |
|---|---|---|---|
| `VBUS_DET` | 输入 | **双边沿必须支持** | 1 = 插在主机上；下降沿后软件有约 20ms 做紧急落盘 |
| `LED_R` | 输出 | — | 红：认证失败 / 无上行 |
| `LED_G` | 输出 | — | 绿：在线且代理可用 |
| `KEY` | 输入 | 支持（去抖由软件做） | 短按 1s = 恢复出厂；长按 5s = 进入恢复模式 |
| `WIFI_RST` | 输出 | — | **必须有**，WiFi 芯片硬复位；无此脚则 WiFi 挂死后只能拔电 |
| `WIFI_WL_EN` | 输出 | — | WiFi 使能 |
| `UART0` TX/RX | — | — | 调试串口 115200 8N1 |
| `SDIO` ×6 | — | — | WiFi（CLK/CMD/D0–D3） |
| `SPI1` ×4 + CS | — | — | **[v0.2] DM9051 以太网专用（独占）** |
| `ETH_INT` | 输入 | **是** | **[v0.2]** DM9051 中断（占用原 EXP-02 名额） |
| `ETH_RST` | 输出 | — | **[v0.2]** DM9051 复位 |
| `VBUS_ADC` | 模拟入 | — | **[v0.2]** VBUS 经 1/3 分压（10k/20k）进 ADC0，量程 5V→1.67V，分压比须标在原理图 |

### 3.2 预留扩展（EXP-01..08）

要求：**8 个未分配 GPIO 引到板边 1.0mm 焊盘**，其中至少 **2 个支持中断**、**2 个支持 PWM**。

中断能力不是每个 GPIO 都有（集中在特定 bank），选脚时必须查 datasheet 确认；软件侧只依赖「至少 2 个」这个承诺。

| 编号 | 预登记用途（软件不假设已接） |
|---|---|
| EXP-01 | 用户按键 2 / 长按组合 |
| EXP-02 | ~~外部 LED 或蜂鸣器~~ **[v0.2] 已被 DM9051 中断占用**，改由 EXP-04 承担 |
| EXP-03 | 温度传感器（I2C 共用 E1） |
| EXP-04 | 风扇 PWM 或第二路 LED |
| EXP-05 | 硬看门狗喂狗线（协处理器 → 主 SoC RESET） |
| EXP-06 | 协处理器 UART（与 E2 共用） |
| EXP-07 | 外部 Flash / 加密芯片 CS |
| EXP-08 | 保留 |

## 4. 分区表（eMMC 4GB，冻结）

| # | 名称 | 大小 | 文件系统 | 说明 |
|---|---|---|---|---|
| 1 | loader | 4MB | raw | BootROM |
| 2 | uboot | 4MB | raw | U-Boot |
| 3 | boot | 32MB | ext4/fat | 内核 + DTB |
| 4 | rootfs_a | 512MB | squashfs | 主系统（只读） |
| 5 | rootfs_b | 512MB | squashfs | 恢复系统（只读） |
| 6 | data | 1GB | ext4/f2fs | 配置、日志、订阅、provider 缓存。**出厂空白，运行期空闲率须 ≥70%** |
| 7 | factory | 16MB | raw/ext4 | MAC、SN、校准数据。**只读挂载** |
| 8 | future | 1GB | 不格式化 | 预留给未来统计库/黑名单。**不格式化**，避免未来重分区（要动 bootloader） |

约束：
- `data` 与 `future` 之间不得再有分区。
- 任何分区大小变更 = 需要重新走产线烧录流程，视为破坏性变更。
- `/run` 用 tmpfs（不占 eMMC 寿命）；日志写 `/data/logs`。

## 5. 电源与时序

| 项 | 要求 |
|---|---|
| 输入 | USB VBUS 5V ±5% |
| 峰值电流 | **[v0.2]** 3.3V 峰值 830mA / 5V 侧 644mA（满档三同时：AP + 有线 + STA）。**软件承诺按 VBUS 三档降档把 5V 侧压在 500mA 内**：full 1.2W / mid 1.0W / low 0.9W |
| 输入电容 | **[v0.2] 3300µF 低 ESR** + 22µF×2 陶瓷 + 100nF（ΔI 由 320mA 涨到 440mA，按 C=ΔI·Δt/ΔV 重算） |
| 限流点 | **[v0.2] 750mA + 必须有软启动**（给 USB3 口跑满留空间；3300µF 的充电电流不软启动会被误判短路） |
| 上电时序 | 以 RV1106 datasheet 为准（规格书 §8 不臆造） |
| 3V3 余量 | 峰值负载不超过额定 40%（留 2.5×）→ **[v0.2] 峰值 830mA 意味着 DCDC 总能力须 ≥2.1A** |
| VBUS 采样 | **[v0.2]** 1/3 分压进 ADC0，每秒采样；这是软件降档的唯一输入信号，缺此项则满档跑在 USB2 口上必然复位 |
| RJ45 座高 | **[v0.2]** 实物卡尺实测 ≤11.5mm，壳内净高 ≥13mm |

**VBUS_DET 语义**：插入主机的瞬间拉高，软件据此启动 gadget；拔出瞬间拉低，软件有 ≤20ms 做紧急落盘（不停机、不 unmount，只 flush 日志）。**不得用 VBUS 直接给 SoC 供电做「有无电」判断**——USB 枚举期间 VBUS 可能抖动。

## 6. 灯与按键的行为契约（用户可见）

| 状态 | LED_R | LED_G | 含义 |
|---|---|---|---|
| 上电 0–3s | 亮 | 灭 | 自检 |
| 自检通过、未连上 WiFi | 灭 | 慢闪（1Hz） | 找 WiFi |
| 已连 WiFi、Portal 未认证 | 慢闪 | 灭 | 等认证 / 认证中 |
| 在线但代理不通 | 亮 | 灭 | 有网但出不去（重点排查项） |
| 一切正常 | 灭 | 亮 | 可用 |
| 恢复模式 | 快闪（4Hz） | 灭 | 长按 KEY 触发 |

按键：短按 1s 松开 = 恢复出厂（清 uci，保留 factory）；长按 5s = 恢复模式（只起 usb0 + 面板，不起 mihomo）。

**软件的判断依据必须是内部状态（`/run/cb/link`、mihomo 探活），不是 LED 本身。LED 只是投影。**
